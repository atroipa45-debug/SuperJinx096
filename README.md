# 📖 بررسی اجمالی

> **Super JinX چیه؟**

Super JinX نسخه‌ی آماده و شخصی‌سازی‌شده‌ی [پاسارگارد](https://github.com/PasarGuard/panel) برای Railway هست. پنل پاسارگارد، هسته‌ی Xray و nginx همه داخل **یک سرویس** اجرا میشن و با اولین دیپلوی، همه‌چیز خودکار ساخته میشه: هسته، نود، ۵ کانفیگ، گروه‌ها، قالب‌ها، نقش نماینده و تنظیمات اشتراک. لازم نیست حتی یه بار وارد تنظیمات پیچیده بشی.

## 🤔 چرا Super JinX؟

> **ساده، خوشگل، خودکار**

- **بدون سرور و بدون ترمینال:** فقط فایل‌ها رو تو گیت‌هاب بذار و به Railway وصل کن.
- **راه‌اندازی صفر تا صد خودکار:** بعد از دیپلوی، پنل آماده‌ی ساخت کاربره.
- **۸ ربات نگهبان:** هر بخشی خراب بشه، فقط همون بخش خودکار درست میشه.
- **همه‌ی لوکیشن‌ها:** روی هر ریجن Railway کار می‌کنه و می‌تونی چند لوکیشن رو به یه پنل وصل کنی.
- **خود پاسارگارد:** پنل همون ظاهر اصلی خودش رو داره، فقط صفحه‌ی اشتراک کاربرها اختصاصی جینکسه.

### ✨ ویژگی‌ها

**🚀 راه‌اندازی خودکار (bootstrap)**
- ساخت خودکار **هسته‌ی JinX-Core** و **نود داخلی**
- ساخت **۵ کانفیگ آماده** با دامنه‌ی Railway، پورت **443** و **TLS**
- ساخت **۳ گروه** و **۱۳ قالب کاربر** (۱۰ تا ۲۰۰ گیگ و نامحدود)

| گروه | کانفیگ‌ها |
| --- | --- |
| ♛ **JinX Royal** | کانفیگ Pro: سریع‌ترین و سازگارترین |
| ◆ **JinX Prime** | ۴ کانفیگ متفاوت: Flash، Fire، Diamond، Night |
| ◈ **JinX Phantom** | همون ۵ کانفیگ با **آی‌پی تمیز**؛ خودش ساخته میشه وقتی لیست آی‌پی رو ذخیره کنی |

- تنظیم خودکار **لینک اشتراک** و عنوان پروفایل
- نقش **نماینده** با دسترسی محدود به کاربرهای خودش + یک **نماینده‌ی نمونه**
- کاربرهایی که بدون گروه ساخته بشن، خودکار به گروه کانفیگ‌ها وصل میشن

**🔐 کانفیگ‌ها**
- **Pro (♛ Royal):** VLESS + WebSocket با early data (سریع‌ترین و سازگارترین)
- **⚡ Flash:** VLESS + WebSocket
- **🔥 Fire:** Trojan + WebSocket
- **💎 Diamond:** VMess + WebSocket
- **🌙 Night:** VLESS + HTTPUpgrade
- **مسیرهای تصادفی** برای هر نصب، با اثرانگشت‌های مختلف (Chrome، Firefox، Safari، Edge، iOS)
- سازگار با v2rayNG، V2Box، Hiddify، Streisand، NekoBox، Happ، Clash Meta و sing-box

**⚡ قدرت پنل**
- دیتابیس در حالت **WAL**: خوندن و نوشتن هم‌زمان، بدون قفل شدن موقع شلوغی
- nginx آماده‌ی **هزاران اتصال هم‌زمان** (۱۶ هزار اتصال در هر هسته)
- تغییر نسخه بدون از دست رفتن کاربر، گروه، قالب یا مسیر کانفیگ‌ها

**🛡️ ۸ ربات نگهبان (guard.py)**
- هر بخش یه ربات جدا داره: **nginx**، **پنل**، **هسته**، **کانفیگ‌ها**، **تونل**، **راه‌اندازی خودکار**، **رم** و **دیتابیس**
- اگه یه بخش خراب بشه، **فقط همون بخش** ری‌استارت میشه، نه کل سرویس (کاربرها قطع نمیشن)
- ربات تونل همون دست‌دادنی رو تست می‌کنه که گوشی کاربر انجام میده
- ربات رم قبل از پر شدن حافظه، هسته رو آروم ری‌استارت می‌کنه
- ربات دیتابیس سلامت دیتابیس رو چک می‌کنه و هر ۶ ساعت **بکاپ خودکار** می‌گیره (۳ تای آخر نگه داشته میشه)
- اگه یه بخش با ۴ بار تعمیر تو ۱۵ دقیقه درست نشد، کل سرویس تمیز ری‌استارت میشه
- صفحه‌ی وضعیت زنده‌ی همه‌ی ربات‌ها روی `/jx-status`

**🌍 چند لوکیشن**
- روی **همه‌ی ریجن‌های Railway** (آمریکا، اروپا، آسیا) کار می‌کنه
- دامنه رو خودش از بازدیدها پیدا می‌کنه، پس کانفیگ‌ها هیچ‌وقت خالی نمی‌مونن
- اسم هر کانفیگ پرچم و اسم لوکیشن خودش رو داره
- با یه **کد اتصال**، یه سرویس توی ریجن دیگه به همین پنل وصل میشه و کانفیگ‌هاش خودکار به ساب همه اضافه میشه

**🧪 آی‌پی تمیز**
- هر کاربر از صفحه‌ی اشتراک خودش **فایل آی‌پی** آپلود می‌کنه (txt، csv، json، رنج CIDR، خروجی اسکنرها)
- هر آی‌پی **واقعاً روی سرور تست میشه**: فقط آی‌پی‌هایی که با دامنه‌ی پنل به همین سرور می‌رسن قبول میشن
- تست دوم از **اینترنت خود کاربر** و انتخاب خودکار بهترین‌ها
- **لینک اشتراک جدا** (`/jx-ip`)، لینک اصلی هیچ‌وقت دستکاری نمیشه
- مالک یه لیست برای **همه** می‌ذاره و گروه **◈ JinX Phantom** با قالب‌هاش **خودکار ساخته میشه**؛ به هر کاربری این گروه رو بدی، کانفیگ‌های آی‌پی رو می‌گیره
- هر ۶ ساعت دوباره تست میشه و آی‌پی‌های مرده خودکار حذف میشن

**🧩 پنل اصلی پاسارگارد، با چند قابلیت بیشتر**
- خود پنل پاسارگارد با **همون تم، رنگ‌ها و زبان‌های خودش** (روشن/تیره و رنگ انتخابی شما)
- منوی ساده‌شده (فقط بخش‌های لازم) و لینک **کانال تلگرام** در منو
- بخش **دسترسی مالک** در صفحه‌ی API Keys: کلید موقت ۵ دقیقه‌ای، تغییر مستقیم رمز، لوکیشن‌ها، آی‌پی تمیز و فعالیت‌های اخیر
- همه‌ی قابلیت‌ها فارسی و انگلیسی، هم‌زبان با پنل

**📱 صفحه‌ی اشتراک کاربر**
- عقربه‌ی **حجم باقی‌مانده**، شمارش معکوس زنده‌ی انقضا و تست سرعت سرور
- **اتصال با یک لمس** به اپ‌ها + لینک دانلود اپ‌ها برای اندروید، آیفون و کامپیوتر
- لیست سرورها با جستجو، فیلتر، **QR** و کپی
- **۴ تم** (طلایی، لیمویی، بنفش، فیروزه‌ای) و حالت سبک برای گوشی‌های ضعیف
- **دستیار هوشمند سیستم** که اگه جایی از صفحه خراب بشه خودش درستش می‌کنه
- تبلیغ کانال با کپسول تلگرام، نوار خبر زنده و پیش‌نمایش کانال
- بدون هیچ فونت یا فایل خارجی، **مناسب اینترنت ایران**

# 🚀 راهنمای نصب

> **شروع سریع** - کمتر از ۱۰ دقیقه، فقط با گوشی

1. یه ریپوی جدید تو **GitHub** بساز.
2. همه‌ی فایل‌های این پروژه رو با **Add file ← Create new file** (یا **Upload files**) کنار هم بذار. **پوشه نساز.**
3. تو **Railway** بزن **New Project ← Deploy from GitHub repo** و همین ریپو رو انتخاب کن.
4. تو تنظیمات سرویس یه **Volume** بساز و مسیرش رو بذار `/var/lib/pasarguard`.
5. تو **Settings ← Networking** بزن **Generate Domain** و پورت رو `8080` بذار.
6. صبر کن تا دیپلوی تموم بشه (حدود ۳ تا ۵ دقیقه).

### 📋 بعد از نصب

**🖥️ پنل مدیریت:** `https://YOUR_DOMAIN/dashboard/`

**🔑 ورود اول:** نام کاربری `admin` و رمز `admin`

**🔒 مهم:** بعد از اولین ورود رمز رو عوض کن. از صفحه‌ی **API Keys** بخش **دسترسی مالک** رو باز کن و یا مستقیم رمز رو عوض کن، یا کلید موقت بگیر، تو صفحه‌ی ورود **دسترسی مالک** رو بزن و رمز جدید بذار.

**👥 نماینده‌ی نمونه:** نام کاربری `reseller` و رمز `reseller` (۵۰ گیگ)

**🛡️ وضعیت ربات‌ها:** `https://YOUR_DOMAIN/jx-status`

**💾 اطلاعات:** همه‌چیز روی Volume در مسیر `/var/lib/pasarguard` ذخیره میشه و با دیپلوی دوباره پاک نمیشه.

# 🌍 لوکیشن‌ها

> **یه پنل، چند کشور**

1. تو پنل برو به **API Keys ← لوکیشن‌ها** و **اضافه کردن لوکیشن جدید** رو بزن تا کد اتصال کپی بشه.
2. تو همون پروژه‌ی Railway یه سرویس جدید از **همین ریپو** بساز.
3. از **Settings ← Region** لوکیشن دلخواه رو انتخاب کن.
4. تو **Variables** بذار: `JINX_MODE=node` و `JINX_CODE=` کد کپی‌شده.
5. تو **Networking** هم **Generate Domain** روی `8080` بزن، هم **TCP Proxy** روی `62050`.
6. یه دقیقه بعد لوکیشن تو پنل دیده میشه و کانفیگ‌هاش به ساب همه‌ی کاربرها اضافه میشه.

| ریجن | اسم توی کانفیگ |
| --- | --- |
| EU West (Amsterdam) | 🇳🇱 هلند |
| US West (California) | 🇺🇸 آمریکا غرب |
| US East (Virginia) | 🇺🇸 آمریکا شرق |
| Asia Southeast (Singapore) | 🇸🇬 سنگاپور |

> سرویس لوکیشن Volume لازم نداره. اسم دلخواه هم می‌تونی با `JINX_LOCATION` بذاری، مثلاً `🇩🇪 آلمان`.

# 🧪 آی‌پی تمیز

> **کانفیگ با آی‌پی، برای اینترنت‌هایی که دامنه رو باز نمی‌کنن**

1. کاربر صفحه‌ی اشتراکش رو باز می‌کنه و تو بخش **سرورها ← آی‌پی تمیز** فایل آی‌پی رو آپلود می‌کنه.
2. سرور همه رو تست می‌کنه، بعد گوشی کاربر پینگ‌شون رو می‌گیره و بهترین‌ها انتخاب میشن.
3. **ذخیره** رو می‌زنه و **لینک اشتراک با آی‌پی** رو تو اپش اضافه می‌کنه.

> توی کانفیگ‌های آی‌پی، آدرس آی‌پی میشه ولی SNI و Host همون دامنه‌ی پنل می‌مونه. روی دامنه‌ی خود Railway آی‌پی‌های Railway جواب میدن؛ اگه دامنه‌ی شخصی رو پشت Cloudflare گذاشتی، آی‌پی‌های Cloudflare هم کار می‌کنن. تست سرور خودش اینو تشخیص میده.

# ⚙️ تنظیمات اختیاری

این متغیرها رو می‌تونی تو **Variables** سرویس Railway بذاری (همه اختیاری‌ان):

| متغیر | پیش‌فرض | توضیح |
| --- | --- | --- |
| `PUBLIC_DOMAIN` | دامنه‌ی Railway | اگه دامنه‌ی شخصی داری |
| `CONFIG_TITLE` | `جینکس \| Super JinX` | متنی که کنار اسم کانفیگ‌ها میاد |
| `DEMO_RESELLER` | `on` | برای نساختن نماینده‌ی نمونه بذار `off` |
| `JINX_MODE` | `panel` | برای سرویس لوکیشن بذار `node` |
| `JINX_CODE` | خالی | کد اتصال لوکیشن (از پنل) |
| `JINX_LOCATION` | خودکار | اسم دلخواه لوکیشن، مثلاً `🇩🇪 آلمان` |

# ❓ سؤال‌های رایج

**یه چیزی کار نمی‌کنه؟**
`/jx-status` رو باز کن، می‌بینی کدوم بخش مشکل داره و ربات‌ها دارن درستش می‌کنن.

**کانفیگ‌ها ساخته نشدن؟**
مطمئن شو **Generate Domain** رو زدی و یه بار پنل رو باز کن، کانفیگ‌ها خودشون ظرف یه دقیقه میان.

**رمز رو یادم رفته؟**
سرویس رو تو Railway ری‌استارت کن، کلید ۵ دقیقه‌ای مالک تو لاگ‌ها چاپ میشه.

**صفحه‌ی اشتراک کجاست؟**
لینک اشتراک هر کاربر رو تو مرورگر باز کن.
